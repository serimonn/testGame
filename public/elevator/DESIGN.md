# エレベーター係の地獄 DESIGN

## 工程0 前提
- ジャンル:2ボタンの見分けアクション。対象:笑いたい人、ゲームに慣れていない人も含む。後で配信者と視聴者の対戦に広げる
- 環境:スマホのブラウザ、縦持ち。PCはキー(Z/←=開、X/→=閉)
- 範囲:今は1人用。配信版は次の段階(配信者のPCのブラウザで `sim.js` を計算し、サーバーは中継だけ)
- 仮定:血や残酷な表現は使わない。ゾンビは緑の肌とぼろ服のコミカルな絵

## 工程1 企画の核
- **一言:** 人間は「開」で乗せ、ゾンビは「閉」で締め出す。ルールはこれだけ
- **分解:** 見て一瞬で判断する気持ちよさと、見間違えたときの笑い
- **考察:** 判断は早いほど楽だが、紛らわしい客は近づくほど手がかり(コーヒー、かばん、緑の耳)がよく見える。待ちすぎると人間は帰り、ゾンビは押し入る
- **再構築:** 1人ずつ扉に来る客を、開か閉かの二択でさばく。階が上がるごとに「ゾンビに見える人間」「人間のふりをするゾンビ」を1組ずつ足す
- **面白さの種類:** ゲーム性は低め、一般性寄り。配分は模倣(エレベーター係)>競争(連続正解)>めまい(大騒ぎの揺れ)。偶然は客の並びだけ
- **独自の魅力:** 開と閉の意味をそのまま使う操作、徹夜明けや顔パックのような「ゾンビにしか見えない人間」、ゾンビを乗せたときの大騒ぎ、締め出したゾンビが扉に顔をぶつける
- **循環:** ストレス=近づく客と待ち時間の輪 / 解消=撃退、ご乗車 / 成長=見分けの手がかりを覚える / 進展=階が上がり新しい客が出る
- **報酬:** 連続正解のほめ言葉、クリアの★(まちがい0で★3)、称号、見分け図鑑
- **最初の3分:** 絵2枚のルール(人間→開、ゾンビ→閉)をタップ。1階はサラリーマンとゾンビだけ。2分ほどで10階に着く
- **遊ぶ時間:** 1回のクリアで約2分〜2分半

## 工程2 設計

### 主要な行動
| 行動 | 正しいとき | まちがいのとき | 待ちすぎ |
|---|---|---|---|
| 開 | 人間が乗る(ご乗車) | ゾンビが乗って大騒ぎ、ライフ−1 | 人間は帰る(ライフ−1)、ゾンビは押し入る(ライフ−1) |
| 閉 | ゾンビが扉に顔をぶつける(撃退) | 人間が顔をぶつけて怒る、ライフ−1 | 同上 |

- 判断の相手は、まだ決めていない客のうち扉に一番近い者。黄色い矢印で示す
- 決めた客の頭に ○(乗せる)か ✕(締め出す)を出す
- 扉の前で待つ間は、残り時間の輪を出す

### 単位とフレーム
- 論理画面 540×960 px、60F 固定刻み。描画が落ちても処理は落とさない
- 客は廊下の端(扉から330px)から歩いてくる

### 階ごとの難しさ(config.js の FLOORS)
| 階 | 新しい客 | 人数 | 待つF | 2人同時 |
|---|---|---|---|---|
| 1 | サラリーマン、ゾンビ | 5 | 90 | なし |
| 2 | おばあちゃん(遅い) | 6 | 80 | なし |
| 3 | 徹夜明け(人間、コーヒー) | 7 | 75 | なし |
| 4 | スーツゾンビ(緑の手を前に) | 7 | 70 | なし |
| 5 | 顔パック(人間、かばん) | 8 | 66 | 10% |
| 6 | マスクゾンビ(耳と首が緑) | 8 | 62 | 15% |
| 7〜9 | 全員 | 9〜12 | 58〜48 | 30〜45% |

- 救済:ライフ3。0になったらその階の最初から、ライフ満タンでやり直し。2回ゲームオーバーで「研修中」(足0.75倍、待ち1.5倍)をすすめる
- タイトルから、前に着いた階で始められる

### 失敗から再操作まで
- まちがい:止め14F、赤い点滅、揺れ、効果音。勤務はそのまま続く
- ゲームオーバー:止め24F、0.5秒後からタップで、その階の扉の前からやり直し

### 画面
- 上:ライフ(ハート3つ)、「○階 → 10階」と10個の升、乗せた人数
- 中:正面から見た扉と、中の乗客
- 下:廊下と客、「開」「閉」の大きなボタン
- 階の最初の5秒だけ、新しい客の見分け方を一言出す。初めて会う客には「NEW」の札

### 音の優先度
1. ゲームオーバー
2. まちがい(悲しいトロンボーン、怒る声)、大騒ぎの悲鳴
3. 撃退(きらり)、扉に顔をぶつける音
4. ご乗車(チャリン)、ゾンビのうめき
5. 到着のチン、扉の開閉
- 館内音楽を流し、空調の環境音を下に敷く

## 第3部の判断
| 分類 | 判断 | 理由や内容 |
|---|---|---|
| A ゲーム性 | 採用(控えめ) | 早く決めるほど楽だが、紛らわしい客は近づくほど手がかりが見える。待ちすぎは失敗 |
| B ジャンル別 | 採用 | ワンボタンのタイミングと早押しの考えを、二択に使う |
| C それ以外の面白さ | 採用 | エレベーター係ごっこと、見間違いの笑い |
| D 報酬 | 採用 | 連続正解のほめ言葉、★、称号、図鑑 |
| E 難易度 | 採用 | 階ごとに紛らわしい組を1つずつ足す |
| F ランダム | 採用 | 客の並びだけ。階の最初の客は固定で、新しい客を落ち着いて見せる |
| G 導入 | 採用 | ルールは絵2枚。説明より先に1階が始まる |
| H シナリオ | 対象外 | 物語はない |
| I リトライ | 採用 | その階から即やり直し |
| J 個性 | 採用 | 紛らわしい組ごとに大きな手がかりを描く |
| K CPU | 対象外 | 客は歩くだけ |
| L 手応え | 採用 | 止め、揺れ、潰れ、星。ジャンプ、カメラ、崖際は対象外 |
| M 快適さ | 採用 | 扉は判断に関係ないので素早く動かす |
| N UI | 採用 | ボタン左右入れ替え、図鑑、研修中 |
| O グラフィック | 採用 | 客はキャンバスで描く。タイトル絵を生成 |
| P モーション | 採用 | ゾンビはぎくしゃく歩く。潰れと伸び |
| Q エフェクト | 採用 | 加算を使わず輪郭付き |
| R サウンド | 採用 | 優先度表どおり |
| S 続編 | 対象外 | 新規作 |
| T 遊びの本質 | 採用 | 工程1の配分 |
| U 姿勢 | 採用 | 遊んでもらった感想で作り直した |

## 決定の記録
- `sim.js` は DOM を使わず、入力(開、閉を押した瞬間)と乱数の種だけで進む:配信版で配信者のブラウザの Web Worker でそのまま動かす
- 判断は客が扉に着く前でもよい。着いた瞬間に結果が出る:早く決める人と、引きつけて見る人の両方が遊べる
- 2人が扉の前で重ならないよう、左右に分かれて待たせる
- 自動プレイ(各30回):判断に20〜45Fかかる人は失敗なし。70Fかかる人は平均約1回ゲームオーバー。紛らわしい客を15%見間違える人は平均約2.5回ゲームオーバー

## 作り直しの経緯
### 1版目(チップと重量の版)
- 内容:開と閉で、走ってくる客を乗せるか締め出すか決める。チップ、重量、9時の始業、社長、押し売り、偽社長、滑り込み、挟み、神閉めがあった
- 感想1:「残り時間、ルール、何をしたらいいのか、全てがわかりにくい」→ 残り秒数、客の頭上の値段札、勤務前の説明、月曜の段階的な案内、押すボタンの点灯を入れた
- 感想2:「面白くない。ルールが可視化されても意味不明。もっと分かりやすいゲームに」
- 判断:原因は表示ではなく、同時に考えることが多すぎたこと。ゲーム性を上げすぎて一般性を失っていた[B-17]。ルールを1つにして作り直す
